# Phase FIN-3 Done — PDF Generation + Share

## What Was Built

Phase FIN-3 adds client-side PDF generation for individual party account statements and a share sheet
(Download, WhatsApp, Email, Print). It also adds a bulk PDF export feature in `FinPartyList` that
generates one PDF per outstanding party, zips them, and downloads as a single `.zip` file.

## Non-obvious Decisions

1. **`buildPDF` always re-fetches** — It does not reuse data already fetched in the Ledger/Outstanding tabs.
   This is intentional: the tab data may not have been fetched yet (tabs are lazy), and the PDF needs all
   three data sources simultaneously. The extra Supabase round-trips are fast for a one-off export action.

2. **WhatsApp + Email both download the PDF** — The Web Share API is not used (no browser support guarantee
   in admin PWA context; file sharing via Web Share requires HTTPS + feature detection). Instead the pattern
   is: download the PDF silently, then open the messaging URL. The user attaches the downloaded file manually.
   This matches real-world usage where WhatsApp Web doesn't accept programmatic file injection.

3. **Print via hidden iframe** — `window.print()` would print the whole admin panel. An iframe loaded with the
   blob URL isolates the print scope to just the PDF. The iframe is removed after 3s.

4. **JSZip lazy import** — `await import('jszip')` keeps it out of the initial JS bundle. Bulk export is an
   occasional admin action; penalising every page load for it would be wrong.

5. **`displayed` used for bulk export targets** — Bulk export always uses the currently displayed (filtered)
   list, not all parties. This means the admin can further refine with the state filter before exporting,
   which is more useful than always exporting every outstanding party.

6. **No `setActiveTab` side-effect in share** — The share button works regardless of which tab is active in
   the slide-over. `buildPDF` fetches ledger + outstanding directly via hooks, independent of tab state.

7. **`handlePin` must remain in the component body** — After adding `shareOpen` state, `handlePin`
   references `party`, `partyType`, `pinLoading`, and `hooks` — all unchanged. It was not moved or modified.

   For `fin_address`: UPSERT on `party_name` (not delete-all, to preserve data for groups beyond
   debtors/creditors).
